Modern CSS

Many former preprocessor jobs now belong to the platform

--custom-properties

Runtime tokens with cascade and inheritance.

& nesting

Related selectors can live together.

@layer

Explicit cascade ordering.

@scope

Bounded selector reach.

calc() / clamp()

Runtime math and fluid values.

color-mix()

Native color relationships.

Sass is still useful, but “CSS cannot do that” is no longer a safe starting assumption.

The browser does not understand SCSS. It receives ordinary CSS generated before the page runs.

Compile Time vs. Runtime

Some decisions happen during the build; others happen in the browser

Compile timeRuntime in the browser
Sass variables, loops, maps, mixinsCSS custom properties, cascade, media queries
Values are resolved before deliveryValues respond to DOM, user settings, and state
Can generate many rulesCan inherit and change without recompiling

A strong architecture uses each stage for the work it is good at.

Do You Need Sass?

Add a build tool only when it solves a real project problem

Need runtime theming?Start with CSS custom properties.
Need selector nesting?Native CSS nesting may be enough.
Need modules and generated APIs?Sass can add meaningful value.
Team already has a build?The operational cost is lower.

Part 1

Modern CSS Alternatives

Use the platform before adding another language

Custom Properties

Live values that participate in the cascade and inheritance

:root {
  --color-accent: #176b5b;
  --space-card: 1.5rem;
}

.card {
  padding: var(--space-card);
  border-color: var(--color-accent);
}

They participate in the cascade, inherit by default, and remain available to DevTools and JavaScript.

Scoped Tokens

Define values as close as possible to where they change

:root {
  --surface: white;
  --text: #172033;
}

[data-theme="dark"] {
  --surface: #172033;
  --text: white;
}

.alert--warning {
  --alert-color: #8a5a00;
}

Global tokens describe the system. Local tokens describe one component or state.

Sass vs. CSS Variables

Compile-time replacement versus live runtime references

Sass

$brand: #176b5b;

.button {
  background: $brand;
}

The value is copied into generated CSS.

CSS

--brand: #176b5b;

.button {
  background: var(--brand);
}

The reference remains live in the browser.

CSS Nesting

Group related selectors without repeating the parent

.card {
  padding: 1.5rem;

  & h2 {
    margin-block: 0 0.5rem;
  }

  &:hover {
    border-color: var(--accent);
  }

  @media (prefers-reduced-motion: no-preference) {
    transition: border-color 180ms ease;
  }
}

Use & when the parent selector must be joined directly to a pseudo-class or modifier.

Nesting Depth

Keep relationships shallow and independent of DOM structure

Related and shallow

.nav {
  & a { ... }
  & a:hover { ... }
}

DOM-shaped specificity

.header {
  .nav {
    ul {
      li { a { ... } }
    }
  }
}

Nesting is for cohesion, not for mirroring every layer of HTML.

Runtime Math

Let the browser calculate fluid values

.page {
  width: min(100% - 2rem, 72rem);
  margin-inline: auto;
}

h1 {
  font-size: clamp(2.25rem, 1.5rem + 3vw, 5rem);
}

.sidebar {
  flex-basis: calc(18rem + var(--panel-offset));
}

These calculations react to the actual browser environment after the CSS has loaded.

Color Functions

Create runtime relationships with color-mix()

:root {
  --brand: oklch(0.55 0.12 190);
  --brand-soft: color-mix(in oklch, var(--brand), white 78%);
  --brand-strong: color-mix(in oklch, var(--brand), black 20%);
}

.button:hover {
  background: var(--brand-strong);
}

Unlike a compiled Sass color, the result can still react when --brand changes at runtime.

Cascade Layers

Define precedence without specificity battles

@layer reset, vendor, base, components, utilities;

@import url("vendor.css") layer(vendor);

@layer components {
  .button { background: var(--accent); }
}

@layer utilities {
  .visually-hidden { ... }
}

Layer order beats specificity across layers, making third-party CSS easier to control.

Layer Priority

Later layers win for normal declarations

reset vendor base components utilities unlayered author styles

For normal declarations, later layers win. Unlayered author rules outrank layered author rules.

@scope

Limit how far selectors can reach

@scope (.artist-card) to (.artist-card__actions) {
  a {
    color: var(--card-link);
  }

  img {
    border-radius: 50%;
  }
}

The styles begin at the scope root and stop before the lower boundary. Inheritance can still cross that boundary.

@property

Give custom properties a type, initial value, and inheritance rule

@property --progress {
  syntax: "<percentage>";
  inherits: false;
  initial-value: 0%;
}

.meter {
  --progress: 72%;
  background: linear-gradient(
    90deg,
    var(--accent) var(--progress),
    #d8dde6 0
  );
}

Registered properties can validate types, control inheritance, and animate more predictably.

Native Architecture

Files, layers, tokens, and naming can provide structure

styles/ tokens.css reset.css base.css components/ button.css artist-card.css utilities.css

Files, layers, tokens, and naming can create structure without a preprocessor.

Part 2

Modern Dart Sass

Local tooling, modules, and maintainable generation

Installation

Use Dart Sass as a project dependency

npm install --save-dev sass
{
  "scripts": {
    "sass:build": "sass scss/main.scss css/styles.css --style=compressed",
    "sass:watch": "sass --watch scss/main.scss css/styles.css"
  }
}

A project-local dependency gives the team the same compiler version and reproducible scripts.

Tooling

Make the build reproducible for every teammate

Editor-only extensionConvenient, but teammates and CI may produce different output. Global installVersion is detached from the project. Project dependencyVersioned, scripted, and repeatable. Bundler integrationUseful when the project already uses Vite or another build tool.

Development and Production

Watch readable source; build optimized output

npm run sass:watch

# Before publishing
npm run sass:build

During development

Readable output and source maps help debugging.

For production

Compressed output reduces transfer size; keep source files in version control.

SCSS Syntax

CSS-compatible syntax with additional language features

$accent: #176b5b;

.button {
  display: inline-flex;
  background: $accent;

  &:hover {
    background: color.scale($accent, $lightness: -18%);
  }
}

Most CSS can be pasted into an SCSS file, then extended with Sass features.

Sass Variables

Use them for build decisions and configuration

$asset-path: "../images";
$include-print-styles: true;
$supported-themes: light, dark, contrast;

.hero {
  background-image: url("#{$asset-path}/hero.webp");
}

Prefer CSS variables for runtime theme values. Use Sass variables for compilation, configuration, and generation.

@import

The legacy global module system is deprecated

Legacy

@import "variables";
@import "buttons";

Global namespace, repeated evaluation, unclear ownership.

Module system

@use "tokens";
@use "buttons";

Namespaced members, loaded once, explicit dependencies.

Dart Sass has emitted deprecation warnings for @import since version 1.80.0.

@use

Load a module once and access its members through a namespace

// _tokens.scss
$accent: #176b5b;
$radius: 0.375rem;

// _card.scss
@use "tokens";

.card {
  border-color: tokens.$accent;
  border-radius: tokens.$radius;
}

tokens is the namespace. The dot reads as: “get this member from that module.”

Namespaces

A prefix that identifies which module owns a member

theme/_tokens.scss 
$radius: 0.25rem;
$accent: #176b5b;
card/_tokens.scss 
$radius: 1rem;
$accent: #8a3ffc;
components/_profile.scss 
@use "../theme/tokens" as theme;
@use "../card/tokens" as card;

.page { color: theme.$accent; }
.card { border-radius: card.$radius; }

Both modules can define $radius because their namespaces prevent a collision.

Namespace Aliases

Use a short local name when a module path is long

Default namespace

@use "components/action-button";

.toolbar {
  gap: action-button.$gap;
}

Readable alias

@use "components/action-button" as button;

.toolbar {
  gap: button.$gap;
}

Aliases are local to the current file. Choose a name that stays clear without being noisy.

@forward

Create one public entry point for several internal modules

settings/ ├── _colors.scss ├── _spacing.scss └── _index.scss main.scss
internal files→settings/_index.scss→main.scss

_index.scss becomes the public door. Consumers do not need to know every internal filename.

Forwarding Example

Expose selected values through one public module

_colors.scss
$accent: #176b5b;
$danger: #a61b1b;
_spacing.scss
$small: 0.5rem;
$large: 2rem;
_index.scss
@forward "colors";
@forward "spacing";
// main.scss: one @use gives access to the forwarded members
@use "settings";

.notice {
  color: settings.$danger;
  padding: settings.$large;
}

Module Configuration

Override !default values when a module is first loaded

// _theme.scss
$accent: #176b5b !default;
$radius: 0.375rem !default;

// main.scss
@use "theme" with (
  $accent: #8a3ffc,
  $radius: 0.125rem
);

Configuration is set when the module is first loaded, so keep module ownership clear.

Mixins

Reuse parameterized groups of declarations

@mixin focus-ring($color: currentColor) {
  outline: 3px solid $color;
  outline-offset: 3px;
}

.button:focus-visible {
  @include focus-ring(#176b5b);
}

.input:focus-visible {
  @include focus-ring(#8a3ffc);
}

A mixin is useful when the reusable unit is a group of declarations, not just one value.

Abstraction Choices

Match the tool to the kind of reuse

Use a...When you need...Example
CSS custom propertyA value that cascades or changes at runtime--accent
Utility classA small declaration available in markup.visually-hidden
Sass mixinA parameterized declaration pattern@include focus-ring
Component classA semantic reusable visual pattern.artist-card

Functions

Accept arguments and return one value

@use "sass:math";

@function rem($pixels, $base: 16) {
  @return math.div($pixels, $base) * 1rem;
}

.caption {
  font-size: rem(14);
}

Use functions for meaningful domain conversions. Native CSS math is preferable when the browser needs to calculate dynamically.

Built-In Modules

Explicit dependencies are named where they are used

Explicit means visible in the source instead of silently available everywhere.

sass:colorColor adjustment and inspection
sass:mathDivision, rounding, powers, units
sass:mapRead and transform maps
sass:listWork with ordered collections
sass:stringInspect and transform strings
sass:metaInspect Sass types and APIs
@use "sass:color";

$hover: color.adjust($accent, $lightness: -12%);

Maps

Store related configuration under named keys

@use "sass:map";

$themes: (
  info: #176b5b,
  warning: #8a5a00,
  danger: #a61b1b
);

.alert--warning {
  --alert-color: #{map.get($themes, warning)};
}

Maps are useful when values form a named set that generation or configuration will consume.

@each

Generate a deliberately small family of related selectors

$statuses: (
  success: #176b5b,
  warning: #8a5a00,
  danger: #a61b1b
);

@each $name, $color in $statuses {
  .status--#{$name} {
    --status-color: #{$color};
  }
}

Generate only classes the product actually needs. A loop can create thousands of unused rules surprisingly quickly.

Generated Output

Elegant source can still produce expensive CSS

3 colors×8 shades×6 properties= 144 rules
7 breakpoints×144 rules= 1,008 variants

Source code can look elegant while its compiled output becomes expensive.

Conditionals

Choose what CSS exists at compile time

$include-print-styles: true;

@if $include-print-styles {
  @media print {
    .site-nav,
    .video-player {
      display: none;
    }
  }
}

Sass conditionals choose what CSS exists. CSS media and feature queries choose what applies in the browser.

@extend

Selector merging can create surprising relationships

%notice-base {
  padding: 1rem;
  border-inline-start: 0.35rem solid;
}

.notice--info {
  @extend %notice-base;
}

.notice--warning {
  @extend %notice-base;
}

@extend merges selectors. That can produce surprising relationships; a mixin or shared class is often easier to reason about.

Parent Selector

Reference the current outer selector with &

.button {
  &--primary { ... }
  &__icon { ... }
  &:hover { ... }
  [data-theme="dark"] & { ... }
}

Sass can concatenate & into class names. Native CSS nesting does not support every Sass concatenation pattern.

Migration

Move from globals to namespaced modules

  1. Find which files define variables, mixins, functions, and CSS output.
  2. Create small module entry points with @forward.
  3. Replace globals with namespaced @use references.
  4. Convert legacy global built-in functions to sass: modules.
  5. Compare compiled CSS before and after the migration.

Sass provides an official migrator, but review its output like any other automated rewrite.

Example Modules

Follow a token from definition to component output

settings/_colors.scss
$accent: #176b5b;
$on-accent: #fff;
tools/_focus-ring.scss
@mixin focus-ring($color) {
  outline: 3px solid $color;
  outline-offset: 3px;
}

.button {
  background: settings.$accent;

Partials beginning with _ are modules. Only main.scss is compiled as an entry point.

Hybrid Source

Generate theme selectors from one Sass map

@use "sass:map";

$themes: (
  light: (surface: #fff, text: #172033),
  dark: (surface: #172033, text: #fff)
);

@each $name, $values in $themes {
  [data-theme="#{$name}"] {
    --surface: #{map.get($values, surface)};
    --text: #{map.get($values, text)};
  }
}

The map is a build-time source of truth. The loop creates only the theme selectors the product supports.

The browser receives ordinary CSS variables it can switch at runtime

Errors and Warnings

Make invalid API usage fail early

@use "sass:math";

@mixin stack($gap) {
  @if not math.compatible($gap, 1rem) {
    @error "$gap must be a length";
  }

  display: flex;
  flex-direction: column;
  gap: $gap;
}

@warn "The $old-radius token is deprecated.";

Fail early when a shared API is used incorrectly; warn when teams need time to migrate.

Key Takeaways

  • Modern CSS now covers variables, nesting, math, cascade organization, scoping, and more.
  • Sass remains valuable for modules, configuration, reusable generators, and build-time logic.
  • Use Dart Sass as a local project dependency with reproducible scripts.
  • Use @use and @forward; legacy Sass @import is deprecated.
  • The compiled CSS is the product. Read it, test it, and keep it understandable.
