Use @supports for Feature Gates

CSS Nesting Keeps Component Rules Together

.card {
  padding: 1rem;
  border: 2px solid currentColor;

  & h2 {
    margin-block: 0 0.5rem;
  }

  &:focus-within {
    outline: 4px solid #e86f51;
  }
}

Browser-native nesting is not Sass. Keep it shallow and readable.

The & Means "This Selector"

Nested CSSEquivalent idea
&:hoverThe component itself in hover state.
&[aria-current="page"]The component itself with an attribute.
& .iconA descendant inside the component.
.toolbar &The component when it appears inside another context.

Nesting At-Rules

.notice {
  background: #fff7d6;
  color: #151923;

  @supports (color: light-dark(black, white)) {
    color: light-dark(#151923, #fff7d6);
    background: light-dark(#fff7d6, #2c2412);
  }
}

Use nested at-rules when the rule belongs to the component.

Nesting Mistakes

Too Deep

.card {
  & .body {
    & ul {
      & li {
        & a { ... }
      }
    }
  }
}

Clearer

.card {
  ...
}

.card-list a {
  ...
}

Exercise

Nesting Refactor

  1. Take a component with five repeated class prefixes.
  2. Nest only the rules that clearly belong together.
  3. Keep nesting to two levels when possible.
  4. Compare specificity before and after.

@scope Limits Selector Reach

@scope (.profile-card) {
  :scope {
    border: 2px solid #151923;
  }

  h2 {
    color: #1f7a68;
  }
}

Scoped rules target a DOM subtree without needing long, defensive selectors.

Scope Root and Scope Limit

@scope (.article-body) to (figure) {
  img {
    border: 5px solid #efc84a;
  }
}
article body paragraph image figure limit

The limit creates a boundary. Rules apply inside the root, but stop before the limit.

Scoping Proximity

Dark scope
Light scope wins for this nested content

When scoped rules conflict, the closest scope root can win before source order matters.

Custom Properties as Component API

.badge {
  --badge-bg: #efc84a;
  --badge-fg: #151923;
  --badge-radius: 999px;

  background: var(--badge-bg);
  color: var(--badge-fg);
  border-radius: var(--badge-radius);
}

Expose the decisions people should change. Hide the rest.

Fallback Values

.callout {
  border-color: var(--callout-border, #1f7a68);
  background: var(--callout-bg, #f4fffb);
  color: var(--callout-fg, #151923);
}

The second value in var() is the fallback if the custom property is missing.

Component Variants With Variables

.callout.warning {
  --callout-border: #efc84a;
  --callout-bg: #fff7d6;
}

.callout.danger {
  --callout-border: #e86f51;
  --callout-bg: #fff0eb;
}

Variants change tokens, not the whole component recipe.

Modern Color Starts With color-scheme

<meta name="color-scheme" content="light dark" />
:root {
  color-scheme: light dark;
}

This tells the browser your page can handle both modes, including form controls and scrollbars.

prefers-color-scheme

:root {
  --surface: #fffdf7;
  --text: #151923;
}

@media (prefers-color-scheme: dark) {
  :root {
    --surface: #151923;
    --text: #fffdf7;
  }
}

light-dark() Removes Repetition

:root {
  color-scheme: light dark;
}

.panel {
  background: light-dark(#fffdf7, #151923);
  color: light-dark(#151923, #fffdf7);
}
Light Dark

color-mix() Builds Related Colors

:root {
  --brand: #1f7a68;
  --brand-soft: color-mix(in oklch, var(--brand) 18%, white);
  --brand-strong: color-mix(in oklch, var(--brand) 70%, black);
}

Use color mixing for consistent tints, borders, hover colors, and theme surfaces.

Why OKLCH Is Useful

Native Disclosure: <details>

<details name="faq">
  <summary>Can I submit late?</summary>
  <p>Check the course policy and speak to your lecturer early.</p>
</details>

Use it for simple show/hide content. The name attribute can create exclusive accordions in supporting browsers.

Modal Tasks Use <dialog>

<button commandfor="help" command="show-modal">Open help</button>

<dialog id="help">
  <h2>Keyboard Help</h2>
  <p>Use Tab to move between controls.</p>
  <button commandfor="help" command="close">Close</button>
</dialog>

Invoker commands let buttons control dialogs declaratively in modern browsers.

Style the Top Layer

dialog {
  border: 3px solid #151923;
  border-radius: 8px;
  padding: 1.5rem;
}

dialog::backdrop {
  background: rgb(21 25 35 / 0.65);
}

::backdrop belongs to dialogs and popovers shown in the top layer.

Popover Is for Non-Modal Floating UI

<button popovertarget="share-menu">Share</button>

<div id="share-menu" popover>
  <a href="#">Copy link</a>
  <a href="#">Send email</a>
</div>

Auto popovers support light dismiss and top-layer behavior without custom JavaScript.

Popover State Selectors

[popover] {
  border: 2px solid #151923;
  padding: 1rem;
}

:popover-open {
  box-shadow: 8px 8px 0 rgb(21 25 35 / 0.18);
}

Use :popover-open for the visible state.

Anchor Positioning Tethers Floating UI

.hint {
  position: absolute;
  inset: auto;
  position-area: top;
}

For popovers, the invoker can be an implicit anchor. The floating element can position itself relative to that anchor.

Explicit Anchors

.avatar {
  anchor-name: --avatar;
}

.profile-card {
  position: absolute;
  position-anchor: --avatar;
  position-area: bottom;
}

Use explicit anchors when the positioned element is not naturally tied to a popover invoker.

Anchor Positioning Needs Fallbacks

.profile-card {
  position: absolute;
  inset-block-start: 100%;
  inset-inline-start: 0;
}

@supports (position-area: bottom) {
  .profile-card {
    inset: auto;
    position-area: bottom;
  }
}

Anchor positioning is new enough that a basic absolute-position fallback is still a good habit.

Form Controls: Start Simple

input,
select,
textarea,
button {
  font: inherit;
}

input[type="checkbox"],
input[type="radio"] {
  accent-color: #1f7a68;
}

accent-color is an easy win for checkboxes, radios, range inputs, and progress-like controls.

appearance Removes Native Styling

input[type="checkbox"] {
  appearance: none;
  inline-size: 1.2em;
  block-size: 1.2em;
  border: 2px solid currentColor;
}

input[type="checkbox"]:checked {
  background: #1f7a68;
}

Only remove native styling when you rebuild states, focus, disabled, and checked visuals.

Customizable Select Is Emerging

select,
::picker(select) {
  appearance: base-select;
}
<select>
  <button><selectedcontent></selectedcontent></button>
  <option>Starter</option>
  <option>Studio</option>
</select>

This is limited availability. Teach it as progressive enhancement, not a requirement.
