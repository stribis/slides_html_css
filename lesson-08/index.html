Accessibility Is Context

Permanent

Blindness, low vision, deafness, motor disability, cognitive disability.

Temporary

Broken arm, eye strain, migraine, lost headphones, slow connection.

Situational

Bright sunlight, noisy train, one-handed use, old device, limited time.

Accessible work is not extra polish. It is resilient design.

The POUR Model

Perceivable Operable Understandable Robust

WCAG organizes accessibility around four questions: can people get the information, use the interface, understand what happens, and rely on it with assistive technology?

WCAG Levels

Level Meaning Classroom target
A Minimum barriers removed. Missing these often blocks users completely. Always meet.
AA Common legal and professional target for public web work. Meet wherever the assignment scope allows.
AAA Enhanced accessibility. Valuable, but not realistic for every page. Use selectively as stretch goals.

WCAG 2.2 Additions Worth Knowing

2.4.11

Focus is not fully hidden behind sticky headers, overlays, or cookie banners.

2.5.7

Dragging has a simple pointer alternative.

2.5.8

Targets are large enough or spaced well enough for real fingers.

3.3.7

Do not make users re-enter the same information unnecessarily.

3.3.8

Authentication does not require hard memory puzzles without alternatives.

3.2.6

Help is easy to find in a consistent location when it exists.

WCAG 3 is still draft work, so teach it as future direction rather than the current grading target.

Keyboard Testing

Key What to check Common failure
TabCan every interactive item be reached?Custom controls skipped.
Shift + TabCan users move backward logically?Focus jumps around the page.
EnterCan links and buttons activate?Fake buttons ignore keyboard input.
SpaceCan checkboxes, buttons, and disclosure widgets operate?Only click events were scripted.
EscapeCan modal UI close safely?Focus gets stuck.

Focus Must Be Visible

Broken

*:focus {
  outline: none;
}

No visible position for keyboard users.

Better

:focus-visible {
  outline: 4px solid #e86f51;
  outline-offset: 4px;
}

Clear focus without showing rings for every mouse click.

Focus Must Not Be Covered

:target,
:focus-visible {
  scroll-margin-block: 6rem;
}

.skip-link:focus-visible {
  position: fixed;
  inset-block-start: 1rem;
  inset-inline-start: 1rem;
}

Sticky nav, cookie banners, and fixed toolbars can hide the focused thing. Leave room for focus to land.

Semantic Structure

<body>
  <a class="skip-link" href="#main">Skip to main content</a>
  <header>...</header>
  <nav aria-label="Primary">...</nav>
  <main id="main">
    <h1>Checkout</h1>
  </main>
  <footer>...</footer>
</body>

Landmarks and headings create the page outline people use to navigate quickly.

Heading Rules

<h1>Main page or view title. <h2>Major page sections. <h3>Subsections inside an <h2>. Do notChoose headings only because of visual size. DoStyle headings with CSS after the structure is correct.

Icon Buttons Need Names

Broken

<button>
  <svg aria-hidden="true">...</svg>
</button>

Better

<button aria-label="Open navigation">
  <svg aria-hidden="true">...</svg>
</button>

Image Alt Text Decisions

InformativeDescribe the information the image contributes. FunctionalDescribe the action, such as "Search" or "Download report". DecorativeUse empty alt: alt="". ComplexSummarize nearby and link to full data if needed. Do notStart with "image of" unless the medium matters.

  4. Check one input in the accessibility tree.

Color and Contrast

Pass

Text has enough contrast against its background.

Fail

Pretty is not enough if people cannot read it.

Do not communicate state with color alone. Pair color with text, icons, shape, or position.

Zoom and Reflow

200%

Text should remain usable when browser zoom increases.

320 CSS px

Layouts should reflow without requiring two-dimensional scrolling for normal content.

rem

Use relative sizing for type and spacing that should respond to user settings.

clamp()

Set type and spacing ranges without locking the page to one viewport.

Exercise

Contrast and Zoom Pass

  2. Increase browser zoom to 200%.
  3. Resize the viewport to a narrow width.
  4. Write down what breaks first and why.

Forms Need More Than Labels

<label for="email">Email address</label>
<input
  id="email"
  name="email"
  type="email"
  autocomplete="email"
  required
  aria-describedby="email-hint"
/>
<p id="email-hint">Use the address for your course account.</p>

Error Messages

<label for="password">Password</label>
<input
  id="password"
  name="password"
  type="password"
  aria-invalid="true"
  aria-describedby="password-error"
/>
<p id="password-error">Password must be at least 12 characters.</p>

Tell users what happened, where it happened, and how to fix it.

Exercise

Form Repair

  1. Connect every visible label to one form control.
  2. Add helpful autocomplete values where possible.
  3. Attach hints and errors with aria-describedby.
  4. Make the error text specific enough to act on.

Motion and Animation

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms;
    animation-iteration-count: 1;
    scroll-behavior: auto;
  }
}

Keep animation purposeful, interruptible, and respectful of user preferences.

Pointer and Touch Targets

Size

Buttons and links need enough area for fingers, tremors, and rushed use.

Spacing

Small targets need extra distance from neighboring actions.

Alternatives

Do not require dragging when a button, field, or menu can do the same job.

Hover

Hover can enhance, but it cannot be the only way to reveal content.

Exercise

Pointer Pass

  1. Find the smallest controls on a page.
  2. Check whether nearby controls are easy to hit without precision.
  3. Find any drag interaction and propose a non-drag alternative.
  4. Check whether hover-only content has a keyboard and touch path.

Native Interaction Patterns

<button>Use for actions. It already supports keyboard activation. <a>Use for navigation to another URL or fragment. <details>Use for simple disclosure without custom JavaScript. <dialog>Use for modal tasks that temporarily take focus. popoverUse for non-modal teaching bubbles, menus, and small overlays.

ARIA Rules

Use native HTML first.

Do not change semantics unless you understand the keyboard pattern too.

ARIA can name and describe. It does not add behavior by itself.

No ARIA is better than wrong ARIA.

Workshop

Open the Accessibility Audit Lab

Open audit lab
  1. Audit the page manually first.
  2. Use the built-in checklist to track issues.
  3. Reveal hints only after your first pass.
  4. Write a repair plan before touching code.

Audit Lab: First Pass

  1. Can you skip repeated navigation?
  2. Can you operate every control with the keyboard?
  3. Can you tell where focus is?
  4. Are headings useful out of context?
  5. Do images and icon buttons have correct names?
  6. Are form fields, hints, and errors connected?

Audit Lab: Repair Sprint

  1. Fix the document structure and skip link.
  2. Repair link and button names.
  3. Repair labels, hints, errors, and autocomplete.
  4. Improve focus, contrast, and target size.
  5. Add reduced-motion handling.
  6. Retest with keyboard and browser zoom.
