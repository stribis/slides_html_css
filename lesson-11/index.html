Libraries and Frameworks

Both provide reusable code; the difference is who controls the application flow

Library

Your code calls the library

Your application→Library function

Choose individual capabilities and call them where they are useful.

Examples: React, Chart.js, Three.js, date-fns
Framework

The framework calls your code

Framework lifecycle→Your components

Work inside an established structure, lifecycle, and set of conventions.

Examples: Angular, Next.js, Astro, Laravel

Reality check: the words are not legal categories. Some tools sit between them, so explain the tool's scope rather than arguing over the label.

CSS Frameworks

Reusable APIs for recurring design decisions

A shared styling system that turns repeated design decisions into a reusable API.

TokensColor, space, type, radii
UtilitiesSmall single-purpose classes
ComponentsButtons, forms, navigation
ConventionsNaming and composition rules

Framework Types

Classless, component-first, utility-first, and token systems

ClasslessStyles semantic HTML automatically <button>Save</button>Pico CSS, Water.css
Component-firstProvides named UI patterns class="btn btn-primary"Bootstrap, Bulma
Utility-firstComposes small styling decisions class="flex gap-4 p-6"Tailwind CSS, UnoCSS
Tokens and primitivesSupplies values rather than complete components gap: var(--size-3)Open Props, design-token packages

“Framework” describes a family of approaches, not one fixed way of writing CSS.

Benefits

Speed, consistency, coverage, and a shared team language

speed

Common patterns already have names, styles, and documentation.

consistency

A shared spacing and color vocabulary reduces accidental variation.

coverage

Many states, screen sizes, and browser quirks are considered.

team language

Developers can discuss the same component and utility API.

Limits

A framework cannot guarantee good HTML, design, or accessibility

Good HTMLYou can still choose the wrong element.Example: <a class="btn">Submit</a> is not a form button. Good designAvailable classes do not make every combination coherent.Example: five unrelated colors and spacing values can all be valid classes. AccessibilityComponents still need correct content, states, labels, and testing.Example: a modal needs a useful name, sensible focus, and keyboard testing. Small CSSImports and unused features still affect output.Example: a full CDN build may include components this page never uses. LongevityYour code depends on another project's upgrade path.Example: renamed utilities or changed markup contracts require migration work.

Framework Choice

Start with the project, not the popularity chart

  1. Are we building a one-off page, a product, or a design system?
  2. Do we need ready-made components or only reusable primitives?
  3. How strongly must the result match a custom visual identity?
  4. Does the team already know the framework?
  5. Can we own upgrades, accessibility checks, and output size?

Entry Files

Imports tell the build tool what belongs to the application

src/main.js

import "bootstrap/dist/css/bootstrap.css";
import "./styles.scss";
import "bootstrap";
Line 1Include Bootstrap's compiled CSS package. Line 2Compile and include our own SCSS. Line 3Include Bootstrap's interactive JavaScript.

The browser never reads node_modules itself. The build tool resolves these imports for it.

npm Scripts

Short, project-owned names for repeatable commands

package.json

{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}

Terminal

npm install

# Before deployment
npm run build

npm run dev means: find the dev script in package.json and execute its command.

Development vs. Production

The local working experience is not the final deployed output

While developing

npm run dev

src/→Vite dev server→localhost
  • Fast updates and useful errors
  • Source files remain easy to debug
  • No deployment folder is required
Before deployment

npm run build

src/→production build→dist/
  • Files are optimized and often minified
  • Hashed names support long-term caching
  • The generated output is deployed

Live Server serves your source folder. A production build creates a new output folder specifically for publishing.

Theme vs. Runtime Variables

Choose whether a value generates utilities or cascades normally

@theme:root
Creates or changes Tailwind utilitiesDefines ordinary runtime custom properties
Design-system vocabularyComponent state or values not meant as utilities
Must be top-levelCan be scoped and overridden through the cascade

Source Detection

Tailwind needs complete class names in source files

Not detectable

`bg-${color}-600`

Complete class names

const variants = {
  info: "bg-cyan-700",
  danger: "bg-red-700",
};

Tailwind scans text; it does not execute your code or understand string interpolation.

Arbitrary Values

Useful exceptions should not become the design system

<div class="top-[117px] w-[43rem] text-[#246bfd]">...</div>
UsefulOne genuine exception or a value from an external specification. Warning signThe same arbitrary value appears throughout the project. Better next stepPromote repeated decisions into a named theme token.

Preflight

Tailwind resets common browser defaults

Margins resetHeadings and paragraphs begin without browser margins. Borders resetBorder style and width have predictable defaults. Images constrainedMedia follows consistent block and sizing behavior. Forms inheritControls use inherited typography and color.

When something “mysteriously” changed, inspect Preflight before adding overrides.

Long Class Lists

Refactor repeated structure without hiding every utility

  1. Keep classes grouped in a consistent order.
  2. Extract repeated markup into a component in your template system.
  3. Use theme tokens so repeated values have names.
  4. Use custom CSS for a coherent component rule when it reads better.
  5. Avoid hiding every utility list behind a custom class immediately.

CSS Knowledge

Utilities are compressed CSS concepts. Understanding the concept is what lets you debug them.

Mixing Frameworks

Define boundaries before combining systems

Reset collisionBoth systems may establish global base styles. Naming collisionGeneric utility or component names can overlap. Bundle growthYou may ship two solutions for the same problem. Team confusionThe same component can be built in incompatible ways.

Key Takeaways

  • A framework is an API for design decisions, not a replacement for HTML and CSS.
  • Bootstrap starts with components; Tailwind starts with composable utilities.
  • Use CDNs for controlled demos and build tools for production projects.
  • Customization, accessibility, output, and upgrades remain your responsibility.
  • The best choice is the smallest system that solves the actual project problem.
