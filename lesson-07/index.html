Video Syntax

<video controls width="640" poster="https://placecats.com/640/360">
  <source src="performance.webm" type="video/webm" />
  <source src="performance.mp4" type="video/mp4" />
  <track kind="captions" src="captions.vtt" srclang="en" label="English" />
  <a href="performance.mp4">Download the video</a>
</video>

Audio Syntax

<audio controls>
  <source src="interview.mp3" type="audio/mpeg" />
  <source src="interview.ogg" type="audio/ogg" />
  <a href="interview.mp3">Download the audio</a>
</audio>

For speech, provide a transcript. For video with speech, provide captions.

When Are iFrames Useful?

maps

Embed a hosted map without building map logic.

videos

Embed YouTube, Vimeo, or internal media platforms.

payments

Secure third-party payment forms.

sandboxes

Isolated previews, demos, or external widgets.

iFrame Pros and Cons

ProsCons
Fast way to include external functionalityLess control over performance and styling
Can isolate risky content with sandboxingThird-party privacy and security concerns
Useful for maps, videos, payments, previewsNeeds a useful title and responsive sizing

What Is a Form?

<form action="/contact" method="post">
  <!-- controls go here -->
  <button type="submit">Send</button>
</form>

A form groups controls and defines how their name/value pairs are submitted.

How Form Data Is Created

<label for="email">Email</label>
<input id="email" name="email" type="email" value="cat@example.com" />

The submitted pair is email=cat@example.com. Without name, most controls are not submitted.

Labels Come Before Styling

<label for="email">Email address</label>
<input id="email" name="email" type="email" autocomplete="email" required />

Placeholder text is not a label. Labels stay available after the user types.

Group Related Fields

<fieldset>
  <legend>Preferred contact method</legend>
  <label><input type="radio" name="contact" value="email" /> Email</label>
  <label><input type="radio" name="contact" value="phone" /> Phone</label>
</fieldset>

Form Example: Contact

<form action="/contact" method="post">
  <label for="name">Name</label>
  <input id="name" name="name" autocomplete="name" required />

  <label for="message">Message</label>
  <textarea id="message" name="message" minlength="20"></textarea>

  <button type="submit">Send</button>
</form>

HTML Validation Attributes

requiredMust be filled before submission minlength maxlengthText length constraints min max stepNumeric or date constraints patternRegular expression for text-like inputs :valid :invalidCSS hooks for validation state

Validation Example

<label for="username">Username</label>
<input
  id="username"
  name="username"
  required
  minlength="3"
  maxlength="20"
  pattern="[a-z0-9-]+"
/>

HTML validation improves UX. Server-side validation is still required.

Form Styling Tips

font: inherit

Make controls match the page typography.

display: grid

Use consistent label/control spacing.

:focus-visible

Never remove focus without replacing it.

accent-color

Quickly theme checkboxes, radios, and range inputs.

Form Styling Example

select,
textarea,

  font: inherit;
}
